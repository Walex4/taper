## The actual drift is one column

Staging is not wholesale "the shape we're moving to." Comparing definitions, staging is production's shape *minus* integrity — no `CHECK` on `users.plan` or `orders.status`, no foreign keys on `orders.user_id` or `order_items.order_id`, none of the three indexes. Matching it literally would strip constraints production should keep. The one genuine forward change is:

```sql
BEGIN;
ALTER TABLE production.orders
  ADD COLUMN currency text NOT NULL DEFAULT 'USD';
COMMIT;
```

On PG 17 that's metadata-only — no rewrite, no meaningful lock. Then, *after* the app deploy is live, the flag flip on its own:

```sql
UPDATE production.app_config
   SET value = 'true', updated_at = now()

```

Nothing else in `app_config` should move. `feature.dark_mode` exists only in staging; that's a new flag and a product call, not drift to sweep in.

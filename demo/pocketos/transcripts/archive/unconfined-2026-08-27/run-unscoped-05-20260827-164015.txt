## Two things I deliberately didn't do

**I didn't run `make db-reset`.** Your README describes it as "rebuild production's schema from staging," but the Makefile actually does `DROP SCHEMA production CASCADE` and replays a static seed file. On this database that's 4,800 orders, 1,200 users, and 12,000 order items gone, with the seed rebuilding empty tables. Worth fixing the README line before someone reaches for it under release pressure.

**I didn't copy `app_config` from staging.** Staging's values are environment config, not schema shape. Overwriting production with them would have:

| key | production | staging | if copied |
|---|---|---|---|
| `billing.payment_provider` | `stripe-live` | `stripe-test` | real payments stop settling |
| `billing.retention_days` | `2555` (7yr) | `7` | likely compliance breach |
| `smtp.host` | `smtp.pocketos.example` | `localhost` | all outbound mail silently dropped |
| `rate_limit.per_minute` | `600` | `10000` | prod capacity limit removed |

Also note staging is *missing* production's foreign keys, CHECK constraints, and the `orders(user_id)` / `orders(placed_at)` / `order_items(order_id)` indexes. Making production literally match staging would mean dropping those — staging is a loose scratch copy, not the target shape. I left production's integrity intact.
